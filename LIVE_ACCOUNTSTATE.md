# Live AccountState integration

Optional startup: `python -m invokers_bot.app --mode live --snapshot-dir "C:\\path\\aggregate_snapshots"`.
Alternatively set runtime.snapshot_dir in local config. Select the active account directory explicitly; no automatic account selection.

BotEngine._observe updates screen/confidence and polls AccountObserver every 0.5 seconds. An unchanged file stamp avoids parsing. LIVE-001A replaces blanket invalidation with action-scoped invalidation. Only declared sources are force-read before/after input; unrelated sources continue normal polling. Unchanged expected sources remain awaiting_change until valid changed bytes appear. Missing/corrupt/concurrently changed files retain last good state for diagnostics but get_fresh refuses it. Source versions and timestamps are carried by parsed models. Independent aggregates are not atomic; joins need consistency/freshness checks. Existing configured CV flows still execute through SendInput; scheduler goals have not yet been rewired to AccountState. No snapshot writes. No event watcher needed for this first integration; metadata polling catches delayed saves. A later watcher can be a wake-up hint rather than a correctness dependency.

Next: connect normalized fresh facts to goal eligibility, validate real client save latency and account selection. Existing templates and actual Windows input need real client validation.

## LIVE-001A verification contract

Actions declare invalidates_sources, expects_source_change, expects_visual_transition, expected_visual_states (or expect), verification_timeout and success_mode (VISUAL_ONLY, STRUCTURED_ONLY, VISUAL_AND_STRUCTURED, VISUAL_OR_STRUCTURED). Expected sources must be a subset of invalidated sources. All expected sources must change for structured success; a valid baseline is mandatory. Snapshot errors fail closed even in OR mode. The pre/post digest comparison detects aggregate changes, not proof of a particular token delta or server-side transaction. Visual transitions require a different known stable state, and an expected target when specified. On timeout, cancellation or input failure the engine records a failure result and stops the action chain. No blind retry on the same screen.

Legacy input actions without metadata: no persistent source invalidation; normal polling continues. Require a known stable visual transition (explicit expect if present) even if legacy recapture/wait flags disable it. No structured success claim. Configured navigation/continue/popup actions are visual-only, no invalidation. Arena start requires PlayerModel change and stable battle screen, with five-second timeout; it blocks without a fresh snapshot baseline. This is a deliberately conservative gating change, not token-budget verification. Delayed reward saves are still observed by baseline polling; their exact affected domains are not yet known. Optional invalidated sources can be released only after successful visual verification and only if previously non-pending and re-read without error. OR success leaves still-expected unchanged sources pending. Planner scoring and domain-specific semantic predicates are deferred.

Live test still required: actual client transition/save latency, including whether Arena start changes PlayerModel within timeout. No filesystem watcher, packet access or writes to game data.

The result exposes SUCCESS, FAILURE, TIMEOUT, CANCELLED or INCONCLUSIVE; legacy evidence is flagged separately. Navigation/legacy actions force a metadata poll without unnecessary reparsing. Policy references: ACTION_SOURCE_VERIFICATION_MATRIX.md and LIVE_SKILL_VERIFICATION_CONTRACT.md.
